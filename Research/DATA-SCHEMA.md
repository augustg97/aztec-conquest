# Data schema — Aztec Conquest

The shapes every data file uses. The data is GENERATED by `Research/modeling/emit.py` from the
research models — do not hand-edit `web/data/*.js`; correct the model and re-emit. The schema is
also visible in each generated file's header comment.

The app's time scalar `t` is a **Julian fractional year** (SCOPE §5): `1521.6137` is
13 August 1521 (Julian). Conversions live in `Research/modeling/calendar.py` only.

---

## The universal fields

Every entity, of every kind, carries these:

```js
{
  id:      "tenochtitlan",         // stable slug; referenced by other records. NEVER recycle.
  name:    "Mēxihco-Tenōchtitlan (Tenochtitlán)",  // ENDONYM FIRST (working rule 2.13)
  kind:    "Triple Alliance seat", // drives the card eyebrow
  layer:   "altepetl" | "works" ,  // which toggle governs it — an id in meta.layers
  lon: -99.1313, lat: 19.4348,     // WGS84, the canonical frame
  from: 1502.0, to: null,          // drawing window (Julian fractional years)
  confidence: "good",              // good | moderate | contested — a FIELD, not a footnote
  note: "",                        // REQUIRED non-empty when confidence is contested
  facts: [["label", "value"], …],  // 2-4 rows, values specific and dated
  eras: [{from, to, text}, …],     // tile [from, T1] exactly — audited (audit_cards)
  sources: ["…"],                  // REQUIRED. A card without a source is an assertion.
}
```

## Allegiance (altepetl entities only)

```js
allegiance: [[1502.0, "tributary"], [1521.0537, "allied-coalition"], …]
```

Step-valued series read with `lastLE`; states from `allegiance.py` STATES; the map colours by
`meta.stateColor[state]`. Every altepetl entity must carry one (audited). Transition instants
come from dated, cited events — the series is DERIVED, never hand-authored.

## Events (`DATA.eventsFull`)

```js
{
  id, t, name, kind,               // kind: political | campaign | battle | massacre |
  precision: "day"|"month"|"year", //        epidemic | siege | aftermath | religious
  lon, lat, confidence,
  facts: [["Date (Julian)", "8 Nov 1519"], ["Gregorian", "18 Nov 1519"],
          ["Nahua day (correlation)", "7 Cipactli — a correlation, not an attestation"]],
  text, sources,
  accounts: [{source, claim, note}, …],   // REQUIRED >= 2 when confidence is contested
  track: true|false,               // part of the Spanish-led column's itinerary polyline
}
```

- Day-precision events carry the Nahua correlation fact, labelled "correlation" (audited).
- `DATA.events` (timeline dots) is the projection `{t, name, id}` of the same list.

## The `accounts:` contract (SCOPE §6 — the central UI decision)

Anything contested carries `accounts`, rendered as **"What the sources say"**: who claims what,
and why each would claim it. The card audit fails a contested card without it. Never resolve a
contested episode silently, in either direction.

## Chapters (`DATA.eras`)

`{from, to, name, title, text}` — must tile `[meta.t0, meta.t1]` exactly (audited).

## Geometry (`DATA.geo`)

```js
DATA.geo = {
  features: [{id, kind: "lake"|"causeway"|"aqueduct"|"dike"|"footprint",
              closed: bool, confidence, points: [[lon, lat], …]}, …],
  anchors:  [{id, lat, lon}, …],   // the archaeological witness table (georef.py)
}
```

Authored at visualization grade against the NAMED reconstruction — González Aparicio (1973) —
and scored against the anchors and literature bands by `audit_witness.py`. Faithful for the
map, not survey-grade; the cards say so.

## Meta (`DATA.meta`)

- `t0: 1502.0, t1: 1551.0, step: 0.02` (≈ one week)
- `timescale: [{from, to, w}, …]` — the NON-LINEAR scrubber: three segments whose `w` weights
  sum to 1; the campaign 1519-1521 gets 56% of the track. The app's `xOf`/`tOf` must be exact
  inverses over it, and the breakpoints are drawn on the track (SCOPE §2).
- `views: {meso, basin, city}` — the three nested scales, as lon/lat extents.
- `layers`, `stateColor`, `stateLabel`, `about` — see `emit.py`.
- `dataVersion` — stamped by the build BEFORE the app file is copied (TRAPS D2).

## Forces (`DATA.forces`)

`[[t, phaseLabel, {contingent: [lo, hi]}], …]` — ranges, never single numbers (working rule
2.14). Rendered as bands.

## Files

- `meta.js` · `eras.js` (chapters + timeline dots) · `entities.js` · `eventsFull.js` · `geo.js`
  — all generated, all assigning into `window.DATA`.
- Data ships as `.js` literals with strict-JSON bodies, so the audits parse the same artifact
  the app executes (TRAPS D5).
